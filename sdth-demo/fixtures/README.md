# Recorded demo fixtures

The six `singapore/` missions plus seven UK flights (`dji_csv_gps_jamming.csv`, `orbiter4_gps_denied_frozen.json`, `dji_csv_motor_fail_recover_024.csv`, `ardupilot_amesbury_alpha.tlog`, `ardupilot_amesbury_alpha.bin`, `hermes900_amesbury_perimeter.stanag`, `aunav_neo_amesbury_patrol.ros`) are auto-imported into the local Mission library on Session connect. The UK set is kept for continuity with the earlier evidence and to show non-DJI formats (Orbiter JSON, ArduPilot TLOG/BIN, Hermes 900 STANAG, aunav ROS); they live in the Stonehenge cache region, so they still get terrain in the replay.
The GPS-warning and dropout CSVs plus the Orbiter JSON are unchanged copies from the original hazard corpus and V2 Orbiter skin. The ArduPilot files are SITL captures from `sdth-synth/out/sitl_proof/` (the `.bin` is a head+tail excerpt, which yields a natural telemetry gap). The STANAG and ROS files are generated by `sdth-telemetry/scripts/generate_multivendor_fixtures.py`.
The `Exercise ·` CSVs are the audited V2 failure-plus-control set.
The two `dji_csv_supplemental_*.csv` files are independent of the original 90-file denominator.
The GPS scenario filename does not prove jamming: the supported observation is a GPS-weak warning.
