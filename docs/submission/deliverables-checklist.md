## Confirmed project decisions

WISL brings recorded drone logs into one searchable view so teams can investigate incidents and review recurring issues across flights. The intended source corpus is `sdth-synth/out/hazards` in the main checkout. Original files remain unchanged. Supplemental controls must be separately labelled and excluded from the original-corpus denominator.

The demo workflow is upload, actual processing status, canonical records, incident evidence and replay, three evidence queries, recurring patterns, a reviewable bulletin and optional local model analysis. Model output is a proposed interpretation, not proof of causality. Fleet analysis uses bounded summaries and incident evidence; it does not read every raw sample into the model context.

Prediction and wearables are future work. LOTR collaboration remains a separate workstream. Q&A is kept brief: value proposition, plausible first user, and why this team.

There is no outreach capability or stakeholder validation. Research can establish plausible contexts and existing alternatives, not demand or endorsement. The incubation ask is facilitated access to operators and representative authorized data.
